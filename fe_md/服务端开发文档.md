## 数据库表设计

### 1. 用户表 (users)

存储系统用户的基本信息。

| 字段名 | 类型 | 长度 | 是否为空 | 主键 | 说明 |
|--------|------|------|----------|------|------|
| id | BIGINT | - | NOT NULL | ✅ | 用户ID，自增主键 |
| user_name | VARCHAR | 50 | NOT NULL | | 用户名，唯一索引 |
| password | VARCHAR | 255 | NOT NULL | | 密码（加密存储，建议使用 BCrypt） |
| nick_name | VARCHAR | 50 | NULL | | 昵称 |
| email | VARCHAR | 100 | NULL | | 邮箱 |
| avatar | VARCHAR | 500 | NULL | | 头像URL |
| user_phone | VARCHAR | 20 | NULL | | 手机号 |
| user_gender | VARCHAR | 10 | NULL | | 性别（'male'/'female'/'unknown'） |
| status | VARCHAR | 10 | NOT NULL | | 状态（'1'启用/'2'禁用），默认'1' |
| create_by | VARCHAR | 50 | NULL | | 创建人 |
| create_time | DATETIME | - | NOT NULL | | 创建时间 |
| update_by | VARCHAR | 50 | NULL | | 更新人 |
| update_time | DATETIME | - | NULL | | 更新时间 |
| remark | VARCHAR | 500 | NULL | | 备注 |

**索引：**
- `UNIQUE INDEX uk_user_name (user_name)` - 用户名唯一索引
- `INDEX idx_status (status)` - 状态索引
- `INDEX idx_create_time (create_time)` - 创建时间索引

**SQL 示例：**
```sql
CREATE TABLE `users` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `user_name` VARCHAR(50) NOT NULL COMMENT '用户名',
  `password` VARCHAR(255) NOT NULL COMMENT '密码',
  `nick_name` VARCHAR(50) DEFAULT NULL COMMENT '昵称',
  `email` VARCHAR(100) DEFAULT NULL COMMENT '邮箱',
  `avatar` VARCHAR(500) DEFAULT NULL COMMENT '头像URL',
  `user_phone` VARCHAR(20) DEFAULT NULL COMMENT '手机号',
  `user_gender` VARCHAR(10) DEFAULT NULL COMMENT '性别',
  `status` VARCHAR(10) NOT NULL DEFAULT '1' COMMENT '状态：1-启用，2-禁用',
  `create_by` VARCHAR(50) DEFAULT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` VARCHAR(50) DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `remark` VARCHAR(500) DEFAULT NULL COMMENT '备注',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_name` (`user_name`),
  KEY `idx_status` (`status`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

存储系统菜单/路由信息，支持多级嵌套结构。

| name | VARCHAR | 100 | NOT NULL | | 路由名称（Vue Router name） |

| icon | VARCHAR | 100 | NULL | | 菜单图标（Iconify 图标名） |

```sql
  `is_hide` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否在菜单中隐藏：1-隐藏，0-显示',
  `is_hide_tab` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否在标签页中隐藏：1-隐藏，0-显示',
  `link` VARCHAR(500) DEFAULT NULL COMMENT '外部链接',
  `is_iframe` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否为iframe：1-是，0-否',
  `keep_alive` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否缓存：1-缓存，0-不缓存',
  `is_first_level` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否为一级菜单：1-是，0-否',
  `fixed_tab` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否固定标签页：1-是，0-否',
  `active_path` VARCHAR(200) DEFAULT NULL COMMENT '激活菜单路径',
  `is_full_page` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否为全屏页面：1-是，0-否',
  `sort_order` INT NOT NULL DEFAULT 0 COMMENT '排序顺序',
  `status` VARCHAR(10) NOT NULL DEFAULT '1' COMMENT '状态：1-启用，2-禁用',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_parent_id` (`parent_id`),
  KEY `idx_status` (`status`),
  KEY `idx_sort_order` (`sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='菜单表';
```

### 4. 菜单权限按钮表 (menu_buttons)

存储菜单下的操作权限按钮（如：新增、编辑、删除等）。

| 字段名 | 类型 | 长度 | 是否为空 | 主键 | 说明 |
|--------|------|------|----------|------|------|
| id | BIGINT | - | NOT NULL | ✅ | 主键ID，自增 |
| menu_id | BIGINT | - | NOT NULL | | 菜单ID，外键关联 menus.id |
| title | VARCHAR | 100 | NOT NULL | | 按钮标题 |
| auth_mark | VARCHAR | 100 | NOT NULL | | 权限标识（如：add, edit, delete） |
| sort_order | INT | - | NOT NULL | | 排序顺序，默认0 |
| create_time | DATETIME | - | NOT NULL | | 创建时间 |

**索引：**
- `INDEX idx_menu_id (menu_id)` - 菜单ID索引
- `UNIQUE INDEX uk_menu_auth (menu_id, auth_mark)` - 菜单和权限标识唯一索引

**SQL 示例：**
```sql
CREATE TABLE `menu_buttons` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `menu_id` BIGINT NOT NULL COMMENT '菜单ID',
  `title` VARCHAR(100) NOT NULL COMMENT '按钮标题',
  `auth_mark` VARCHAR(100) NOT NULL COMMENT '权限标识',
  `sort_order` INT NOT NULL DEFAULT 0 COMMENT '排序顺序',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_menu_id` (`menu_id`),
  UNIQUE KEY `uk_menu_auth` (`menu_id`, `auth_mark`),
  CONSTRAINT `fk_menu_buttons_menu` FOREIGN KEY (`menu_id`) REFERENCES `menus` (`id`) ON DELETE CASCADE

```

## 鉴权方案

### 1. JWT Token 认证

系统采用 JWT (JSON Web Token) 进行用户认证，使用双 Token 机制（Access Token + Refresh Token）。

#### 1.1 Token 结构

**Access Token（访问令牌）**
- 用途：用于 API 请求认证
- 有效期：较短（建议 2-4 小时）
- 存储位置：前端 localStorage
- 请求头：`Authorization: {token}`

**Refresh Token（刷新令牌）**
- 用途：用于刷新 Access Token
- 有效期：较长（建议 7-30 天）
- 存储位置：前端 localStorage
- 使用场景：Access Token 过期时自动刷新

#### 1.2 Token 生成规则

```javascript
// Access Token Payload 示例
{
  "userId": 1,
  "userName": "admin",
  "roles": ["admin", "user"],
  "iat": 1234567890,  // 签发时间
  "exp": 1234571490   // 过期时间（2小时后）
}

// Refresh Token Payload 示例
{
  "userId": 1,
  "type": "refresh",
  "iat": 1234567890,
  "exp": 1235172690   // 过期时间（7天后）
}
```

#### 1.3 登录流程

```
1. 用户提交用户名和密码
   ↓
2. 后端验证用户名和密码
   ↓
3. 验证成功，生成 Access Token 和 Refresh Token
   ↓
4. 返回 Token 给前端
   ↓
5. 前端存储 Token 到 localStorage
   ↓
6. 后续请求在请求头中携带 Access Token
```

**登录接口示例：**

**请求：**
```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "userName": "admin",
  "password": "123456"
}
```

**响应：**
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

#### 1.4 Token 刷新流程

```
1. Access Token 过期，请求返回 401
   ↓
2. 前端检测到 401，自动调用刷新接口
   ↓
3. 使用 Refresh Token 请求新的 Access Token
   ↓
4. 后端验证 Refresh Token 有效性
   ↓
5. 验证成功，返回新的 Access Token（可选：返回新的 Refresh Token）
   ↓
6. 前端更新 Access Token，重新发起原请求
```

**刷新 Token 接口示例：**

**请求：**
```http
POST /api/v1/auth/refresh
Content-Type: application/json

{
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**响应：**
```json
{
  "code": 200,
  "message": "刷新成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."  // 可选
  }
}
```

#### 1.5 权限验证中间件

后端需要在每个需要认证的接口上添加权限验证中间件：

**伪代码示例：**
```javascript
// 1. 验证 Token 是否存在
if (!token) {
  return { code: 401, message: '未授权，请先登录' }
}

// 2. 验证 Token 有效性
const decoded = jwt.verify(token, SECRET_KEY)
if (!decoded) {
  return { code: 401, message: 'Token 无效或已过期' }
}

// 3. 验证用户状态
const user = await getUserById(decoded.userId)
if (user.status !== '1') {
  return { code: 401, message: '用户已被禁用' }
}

// 4. 将用户信息附加到请求对象
req.user = {
  userId: decoded.userId,
  userName: decoded.userName,
  roles: decoded.roles
}
```

#### 1.6 获取用户信息接口

登录成功后，前端需要调用获取用户信息接口，获取用户的角色、权限等信息。

**请求：**
```http
GET /api/v1/user/info
Authorization: {token}
```

**响应：**
```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "userId": 1,
    "userName": "admin",
    "email": "admin@example.com",
    "avatar": "https://example.com/avatar.jpg",
    "roles": ["admin"],
    "buttons": ["add", "edit", "delete", "view"]  // 按钮权限列表
  }
}
```

**注意：**
- `roles` 字段：用户拥有的角色列表，用于菜单权限过滤
- `buttons` 字段：用户拥有的按钮权限列表，用于前端按钮显示控制

## 动态路由实现

### 1. 菜单数据结构

前端期望的菜单数据结构需要符合 `AppRouteRecord` 接口定义：

```typescript
interface AppRouteRecord {
  id?: number
  name: string              // 路由名称（Vue Router name）
  path: string              // 路由路径
  component?: string         // 组件路径（如：views/system/user/index.vue）
  meta: {
    title: string           // 菜单标题
    icon?: string           // 菜单图标（Iconify 图标名）
    isHide?: boolean        // 是否在菜单中隐藏
    isHideTab?: boolean     // 是否在标签页中隐藏
    link?: string          // 外部链接
    isIframe?: boolean     // 是否为 iframe
    keepAlive?: boolean    // 是否缓存
    roles?: string[]       // 角色权限（可选）
```

#### 3.2 构建菜单树结构

将扁平化的菜单数据转换为树形结构：

**伪代码示例：**
```javascript
function buildMenuTree(menus, parentId = 0) {
  const tree = []
  
  for (const menu of menus) {
    if (menu.parent_id === parentId) {
      const menuNode = {
        id: menu.id,
        name: menu.name,
        path: menu.path,
        component: menu.component,
        meta: {
          title: menu.title,
          icon: menu.icon,
          isHide: menu.is_hide === 1,
          isHideTab: menu.is_hide_tab === 1,
          link: menu.link,
          isIframe: menu.is_iframe === 1,
          keepAlive: menu.keep_alive === 1,
          isFirstLevel: menu.is_first_level === 1,
          fixedTab: menu.fixed_tab === 1,
          activePath: menu.active_path,
          isFullPage: menu.is_full_page === 1
        }
      }
      
      // 查询子菜单
      const children = buildMenuTree(menus, menu.id)
      if (children.length > 0) {
        menuNode.children = children
      }
      
      // 查询菜单按钮权限
      const buttons = await getMenuButtons(menu.id, roleIds)
      if (buttons.length > 0) {
        menuNode.meta.authList = buttons.map(btn => ({
          title: btn.title,
          authMark: btn.auth_mark
        }))
      }
      
      tree.push(menuNode)
    }
  }
  
  return tree
}
```

### 4. 路径规范

#### 4.1 路径规则

- **一级菜单**：路径必须以 `/` 开头，如 `/system`、`/dashboard`
- **二级及以下菜单**：路径不能以 `/` 开头，使用相对路径，如 `user`、`role`
- **外部链接**：完整的 URL，如 `https://example.com`
- **iframe 路由**：路径以 `/outside/iframe/` 开头

#### 4.2 路径拼接规则

前端会自动将子菜单路径拼接到父菜单路径后面：
- 父菜单：`/system`
- 子菜单：`user`
- 最终路径：`/system/user`

#### 4.3 组件路径规范

- **布局组件**：使用 `Layout` 字符串（不需要 .vue 后缀）
- **页面组件**：使用完整路径，如 `views/system/user/index.vue`
- **外部链接**：不需要 component 字段

### 5. 权限过滤

#### 5.1 菜单权限过滤

后端在查询菜单时，只返回用户有权限访问的菜单。前端会根据菜单列表动态注册路由，没有权限的菜单不会出现在路由中。

#### 5.2 按钮权限过滤

后端在返回菜单数据时，需要包含该用户在该菜单下的按钮权限列表（`authList`）。前端会根据 `authList` 控制按钮的显示/隐藏。

**查询用户按钮权限的 SQL：**
```sql
SELECT DISTINCT mb.auth_mark
FROM menu_buttons mb
INNER JOIN role_menu_buttons rmb ON mb.id = rmb.button_id
INNER JOIN user_roles ur ON rmb.role_id = ur.role_id
WHERE ur.user_id = ?
  AND mb.menu_id = ?
```

## 开发注意事项

### 1. 密码加密

- 使用 BCrypt 或 Argon2 加密存储密码
- 不要使用 MD5、SHA1 等弱加密算法
- 密码强度要求：至少 8 位，包含字母和数字

### 2. Token 安全

- Token 密钥要足够复杂，建议使用随机生成的 32 位以上字符串
- Access Token 有效期不宜过长，建议 2-4 小时
- Refresh Token 需要单独存储，支持黑名单机制
- 支持 Token 撤销功能（登出时）

### 3. 权限控制

- 所有需要权限的接口都要验证 Token
- 菜单权限和按钮权限要分开控制
- 支持角色继承（可选）
- 权限变更后，需要重新登录或刷新 Token

### 4. 数据安全

- 使用参数化查询防止 SQL 注入
- 对用户输入进行验证和过滤
- 敏感数据（如密码）不要返回给前端
- 使用 HTTPS 传输数据

### 5. 性能优化

- 菜单查询结果可以缓存（Redis），用户权限变更时清除缓存
- 使用数据库索引优化查询性能
- 分页查询要限制最大页大小
- 避免 N+1 查询问题

### 6. 错误处理

- 统一的错误响应格式
- 详细的错误日志记录
- 不要向客户端暴露敏感信息（如数据库错误详情）

### 7. 接口版本控制

- 使用 URL 版本控制：`/api/v1/xxx`
- 向后兼容，新版本不影响旧版本
- 废弃接口要提前通知

### 8. 测试建议

- 单元测试：每个接口都要有测试用例
- 集成测试：测试完整的业务流程
- 安全测试：测试 SQL 注入、XSS 等安全问题
- 性能测试：测试接口响应时间和并发能力
