# 启动指南 - 开发与生产环境

## 📋 快速参考

### 开发环境

```bash
pnpm start:dev
```

- 自动加载 `.env.development`
- 启用热重载（watch 模式）
- 日志级别：`debug`

### 生产环境

```bash
# 1. 先构建
pnpm build:prod

# 2. 启动
pnpm start:prod
```

- 自动加载 `.env.production`
- 优化后的生产构建
- 日志级别：`info`

---

## 🚀 详细说明

### 开发环境启动

#### 方式一：使用 npm 脚本（推荐）

```bash
pnpm start:dev
```

**说明：**

- 自动设置 `NODE_ENV=development`
- 自动加载 `.env.development` 配置文件
- 启用文件监听，代码修改后自动重启
- 适合日常开发使用

#### 方式二：手动指定环境

```bash
NODE_ENV=development pnpm start:dev
```

#### 方式三：使用 nest 命令

```bash
NODE_ENV=development nest start --watch
```

---

### 生产环境启动

#### 完整流程

**步骤 1：构建项目**

```bash
pnpm build:prod
```

- 自动设置 `NODE_ENV=production`
- 编译 TypeScript 代码到 `dist/` 目录
- 优化生产构建

**步骤 2：启动应用**

```bash
pnpm start:prod
```

- 自动设置 `NODE_ENV=production`
- 自动加载 `.env.production` 配置文件
- 运行编译后的 JavaScript 代码

#### 一键启动（生产环境）

```bash
pnpm build:prod && pnpm start:prod
```

---

## 🔧 其他启动命令

### 调试模式（开发环境）

```bash
pnpm start:debug
```

- 启用 Node.js 调试器
- 可以在 VS Code 或其他调试工具中附加调试器
- 默认端口：`9229`

### 普通启动（不推荐）

```bash
pnpm start
```

- 不设置 `NODE_ENV`，会使用默认值 `development`
- 不启用文件监听
- 适合快速测试

## 📁 环境配置文件

### 配置文件加载顺序

系统会按以下顺序加载配置文件（后加载的会覆盖先加载的）：

1. **`.env`** - 公共配置（基础配置，所有环境共享）
   - 包含所有环境共用的配置项
   - 如：PORT、DB_HOST、DB_PORT、DB_USERNAME、JWT_EXPIRES_IN 等

2. **`.env.${NODE_ENV}`** - 环境特定配置（覆盖公共配置）
   - `NODE_ENV=development` → 加载 `.env.development`
   - `NODE_ENV=production` → 加载 `.env.production`
   - 只包含该环境特有的配置，会覆盖 `.env` 中的同名配置

### 配置文件说明

| 文件               | 用途                     | 是否提交 Git |
| ------------------ | ------------------------ | ------------ |
| `.env`             | 公共配置（所有环境共享） | ✅ 是        |
| `.env.development` | 开发环境特有配置         | ✅ 是        |
| `.env.production`  | 生产环境特有配置         | ✅ 是        |

**配置原则：**

- `.env` 中只放公共配置，避免重复
- 环境特定文件只放该环境独有的配置
- 如果某个配置在所有环境都相同，放在 `.env` 中
- 如果某个配置在不同环境不同，放在对应的环境文件中

## 🎯 环境变量说明

### 公共配置 (`.env`)

```env
PORT=3000
DB_HOST=localhost
DB_PORT=3306
DB_USERNAME=root
JWT_EXPIRES_IN=7d

# Redis 配置（公共）
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_DB=0
REDIS_KEY_PREFIX=qm_photo:
```

### 开发环境特有配置 (`.env.development`)

```env
NODE_ENV=development
DB_DATABASE=qm_photo_db_dev
DB_PASSWORD=123456
DATABASE_URL="mysql://root:123456@localhost:3306/qm_photo_db_dev"
JWT_SECRET=dev-secret-key
CORS_ORIGIN=http://localhost:3000
LOG_LEVEL=debug

# Redis 配置（开发环境）
REDIS_PASSWORD=
REDIS_CONNECT_TIMEOUT=10000
REDIS_LAZY_CONNECT=false
REDIS_MAX_RETRIES=3
REDIS_ENABLE_READY_CHECK=true
REDIS_ENABLE_OFFLINE_QUEUE=true
```

### 生产环境特有配置 (`.env.production`)

```env
NODE_ENV=production
DB_DATABASE=qm_photo_db_prod
DB_PASSWORD=YOUR_PRODUCTION_PASSWORD
DATABASE_URL="mysql://root:YOUR_PRODUCTION_PASSWORD@localhost:3306/qm_photo_db_prod"
JWT_SECRET=YOUR_SUPER_SECRET_JWT_KEY
CORS_ORIGIN=https://yourdomain.com
LOG_LEVEL=info

# Redis 配置（生产环境）
REDIS_PASSWORD=YOUR_REDIS_PASSWORD
REDIS_CONNECT_TIMEOUT=10000
REDIS_LAZY_CONNECT=false
REDIS_MAX_RETRIES=3
REDIS_ENABLE_READY_CHECK=true
REDIS_ENABLE_OFFLINE_QUEUE=true
```

⚠️ **重要：** 生产环境部署前，必须修改 `.env.production` 中的敏感信息：

- `JWT_SECRET` - 使用强随机字符串
- `DB_PASSWORD` - 使用强密码
- `REDIS_PASSWORD` - 使用强密码（如果启用了 Redis 密码）
- `CORS_ORIGIN` - 配置实际域名

## 🐛 常见问题

### Q1: 如何确认当前使用的环境？

启动应用后，查看控制台输出：

```
🚀 应用运行在: http://localhost:3000
📦 环境: development  # 或 production
```

### Q2: 如何临时覆盖环境变量？

```bash
# 临时修改端口
PORT=4000 pnpm start:dev

# 临时修改数据库
DB_HOST=192.168.1.100 pnpm start:dev
```

### Q3: 生产环境启动失败？

1. 确保已执行 `pnpm build:prod`
2. 检查 `dist/` 目录是否存在
3. 确认 `.env.production` 文件存在且配置正确
4. 检查端口是否被占用

### Q4: 如何在不同端口启动？

修改对应环境的 `.env` 文件中的 `PORT` 值，或使用：

```bash
PORT=4000 pnpm start:dev
```

## 📝 脚本命令总结

| 命令               | 环境        | 说明                   |
| ------------------ | ----------- | ---------------------- |
| `pnpm start:dev`   | development | 开发环境，热重载       |
| `pnpm start:prod`  | production  | 生产环境，需先构建     |
| `pnpm start:debug` | development | 开发环境，调试模式     |
| `pnpm build:prod`  | production  | 生产构建               |
| `pnpm build`       | -           | 普通构建（不指定环境） |

---

## 💡 最佳实践

1. **开发时**：始终使用 `pnpm start:dev`
2. **部署前**：使用 `pnpm build:prod` 构建
3. **生产环境**：使用 `pnpm start:prod` 启动
4. **调试时**：使用 `pnpm start:debug` 并附加调试器
5. **公共配置**：放在 `.env` 中，避免在环境文件中重复
