## 方案一：Webhook 自动部署（推荐）

### 工作原理

1. GitHub Actions 构建完成后，调用服务器 Webhook API
2. 服务器接收 Webhook 请求，触发自动部署脚本
3. 自动拉取新镜像并重启服务

### 1. 配置 GitHub Actions Webhook

在 GitHub Actions 工作流中添加 Webhook 通知步骤：

```yaml
# 在 .github/workflows/deploy.yml 的 build-and-push job 最后添加
- name: Notify server to deploy
  if: success()
  run: |
    curl -X POST "${{ secrets.DEPLOY_WEBHOOK_URL }}" \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer ${{ secrets.DEPLOY_WEBHOOK_TOKEN }}" \
      -d '{
        "tag": "${{ steps.image-tag.outputs.tag }}",
        "image": "${{ env.REGISTRY }}/${{ env.NAMESPACE }}/${{ env.IMAGE_NAME }}:${{ steps.image-tag.outputs.tag }}",
        "status": "success",
        "commit": "${{ github.sha }}",
        "branch": "${{ github.ref_name }}"
      }'
```

### 2. 配置 GitHub Secrets

在 GitHub 仓库中添加以下 Secrets：

- `DEPLOY_WEBHOOK_URL`: 服务器 Webhook 接收地址（如：`https://your-server.com/api/deploy/webhook`）
- `DEPLOY_WEBHOOK_TOKEN`: Webhook 认证令牌（用于验证请求合法性）

### 3. 创建服务器端 Webhook 接收服务

#### 方案 3.1：使用 Node.js 简单 Webhook 服务

创建 `scripts/webhook-server.js`：

```javascript
const http = require('http');
const { exec } = require('child_process');
const path = require('path');

const WEBHOOK_TOKEN = process.env.WEBHOOK_TOKEN || 'your-secret-token';
const DEPLOY_SCRIPT = path.join(__dirname, 'deploy-from-registry.sh');
const PORT = process.env.WEBHOOK_PORT || 3009;

const server = http.createServer((req, res) => {
  if (req.method !== 'POST' || req.url !== '/api/deploy/webhook') {
    res.writeHead(404);
    res.end('Not Found');
    return;
  }

  let body = '';
  req.on('data', (chunk) => {
    body += chunk.toString();
  });
  req.on('end', () => {
    try {
      // 验证 Token
      const authHeader = req.headers.authorization;
      if (!authHeader || !authHeader.startsWith('Bearer ')) {
        res.writeHead(401);
        res.end('Unauthorized');
        return;
      }

      const token = authHeader.substring(7);
      if (token !== WEBHOOK_TOKEN) {
        res.writeHead(401);
        res.end('Invalid Token');
        return;
      }

      // 解析请求体
      const data = JSON.parse(body);
      const { tag, image, status } = data;

      if (status !== 'success') {
        res.writeHead(200);
        res.end('Build failed, skip deployment');
        return;
      }

      console.log(`[${new Date().toISOString()}] 收到部署请求: ${image}`);

      // 执行部署脚本
      exec(`bash ${DEPLOY_SCRIPT} ${tag}`, (error, stdout, stderr) => {
        if (error) {
          console.error(`部署失败: ${error.message}`);
          res.writeHead(500);
          res.end(JSON.stringify({ error: error.message }));
          return;
        }

        console.log(`部署成功: ${stdout}`);
        res.writeHead(200);
        res.end(
          JSON.stringify({
            success: true,
            message: 'Deployment triggered',
            tag,
            image,
          }),
        );
      });
    } catch (error) {
      console.error('处理 Webhook 请求失败:', error);
      res.writeHead(400);
      res.end(JSON.stringify({ error: error.message }));
    }
  });
});

server.listen(PORT, () => {
  console.log(`Webhook 服务器启动在端口 ${PORT}`);
  console.log(`Token: ${WEBHOOK_TOKEN}`);
});
```

#### 方案 3.2：使用 Nginx + 简单脚本（更轻量）

创建 `scripts/webhook-handler.sh`：

```bash
#!/bin/bash

# Webhook 处理脚本
# 配合 Nginx 使用，Nginx 将请求转发到此脚本

WEBHOOK_TOKEN="your-secret-token"
DEPLOY_SCRIPT="$(dirname "$0")/deploy-from-registry.sh"

# 读取请求体
read -r BODY

# 验证 Token（从 Header 获取，需要 Nginx 传递）
TOKEN="${HTTP_AUTHORIZATION#Bearer }"

if [ "$TOKEN" != "$WEBHOOK_TOKEN" ]; then
    echo "HTTP/1.1 401 Unauthorized"
    echo "Content-Type: application/json"
    echo ""
    echo '{"error": "Invalid token"}'
    exit 1
fi

# 解析 JSON（使用 jq，需要安装）
TAG=$(echo "$BODY" | jq -r '.tag // "latest"')
STATUS=$(echo "$BODY" | jq -r '.status')

if [ "$STATUS" != "success" ]; then
    echo "HTTP/1.1 200 OK"
    echo "Content-Type: application/json"
    echo ""
    echo '{"message": "Build failed, skip deployment"}'
    exit 0
fi

# 执行部署（异步执行，避免阻塞）
bash "$DEPLOY_SCRIPT" "$TAG" > /tmp/deploy.log 2>&1 &

echo "HTTP/1.1 200 OK"
echo "Content-Type: application/json"
echo ""
echo "{\"message\": \"Deployment triggered\", \"tag\": \"$TAG\"}"
```

### 4. 使用 PM2 运行 Webhook 服务

```bash
# 安装依赖（如果需要）
npm install

# 使用 PM2 启动 Webhook 服务
pm2 start scripts/webhook-server.js --name webhook-server

# 设置开机自启
pm2 save
pm2 startup
```

### 5. 配置 Nginx 反向代理（可选）

```nginx
# /etc/nginx/sites-available/webhook
server {
    listen 80;
    server_name your-server.com;

    location /api/deploy/webhook {
        proxy_pass http://localhost:3009;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Authorization $http_authorization;
        proxy_set_header Content-Type $content_type;
    }
}
```

## 方案二：定时轮询检查

### 工作原理

服务器定时检查镜像仓库是否有新版本，发现新版本后自动部署。

### 实现步骤

#### 1. 创建轮询脚本

创建 `scripts/auto-deploy-poll.sh`：

```bash
#!/bin/bash

# 定时轮询检查新镜像并部署

REGISTRY="crpi-eg9062f6byi3012b.cn-chengdu.personal.cr.aliyuncs.com"
NAMESPACE="dawn_dockers"
IMAGE_NAME="qm-photo-server"
CURRENT_TAG_FILE="/tmp/current-image-tag.txt"
DEPLOY_SCRIPT="$(dirname "$0")/deploy-from-registry.sh"

# 获取当前使用的镜像标签
get_current_tag() {
    if [ -f "$CURRENT_TAG_FILE" ]; then
        cat "$CURRENT_TAG_FILE"
    else
        echo "latest"
    fi
}

# 检查镜像是否有新版本
check_new_version() {
    local current_tag=$(get_current_tag)

    # 拉取镜像 manifest 检查更新时间
    # 这里简化处理，实际可以调用阿里云 API 或使用 docker manifest inspect
    echo "检查新版本，当前标签: $current_tag"

    # 尝试拉取 latest 标签
    docker pull "${REGISTRY}/${NAMESPACE}/${IMAGE_NAME}:latest" > /dev/null 2>&1

    if [ $? -eq 0 ]; then
        # 检查镜像 ID 是否变化
        local new_image_id=$(docker images --format "{{.ID}}" "${REGISTRY}/${NAMESPACE}/${IMAGE_NAME}:latest" | head -1)
        local current_image_id=$(docker images --format "{{.ID}}" "${REGISTRY}/${NAMESPACE}/${IMAGE_NAME}:${current_tag}" | head -1)

        if [ "$new_image_id" != "$current_image_id" ]; then
            echo "发现新版本！"
            return 0
        fi
    fi

    return 1
}

# 执行部署
deploy() {
    local tag=${1:-"latest"}
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] 开始部署标签: $tag"

    bash "$DEPLOY_SCRIPT" "$tag"

    if [ $? -eq 0 ]; then
        echo "$tag" > "$CURRENT_TAG_FILE"
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] 部署成功"
    else
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] 部署失败"
        exit 1
    fi
}

# 主逻辑
main() {
    if check_new_version; then
        deploy "latest"
    else
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] 无新版本"
    fi
}

main
```

#### 2. 配置 Crontab

```bash
# 编辑 crontab
crontab -e

# 每 5 分钟检查一次
*/5 * * * * /path/to/scripts/auto-deploy-poll.sh >> /var/log/auto-deploy.log 2>&1
```

## 部署脚本说明

### deploy-from-registry.sh 脚本功能

该脚本执行以下步骤：

1. **检查环境**：验证 `.env.production` 文件是否存在
2. **登录 Registry**：自动登录阿里云容器镜像服务
3. **拉取镜像**：从 registry 拉取指定标签的镜像
4. **启动依赖服务**：启动 MySQL 和 Redis（如果未运行）
5. **数据库迁移**：运行 Prisma 数据库迁移
6. **启动应用**：使用 Docker Compose 启动应用服务
7. **健康检查**：验证服务是否正常启动

### 使用方法

```bash
# 基本用法
./scripts/deploy-from-registry.sh [tag]

# 示例
./scripts/deploy-from-registry.sh latest          # 部署 latest 标签
./scripts/deploy-from-registry.sh a1b2c3d        # 部署指定 commit SHA
./scripts/deploy-from-registry.sh v1.0.0         # 部署版本标签
```

### 环境变量配置

确保服务器上有 `.env.production` 文件，包含以下配置：

```env
# 数据库配置
DB_HOST=mysql
DB_PORT=3306
DB_USERNAME=your_username
DB_PASSWORD=your_password
DB_DATABASE=your_database

# Redis 配置
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=your_redis_password

# JWT 配置
JWT_SECRET=your_jwt_secret

# 其他配置...
```

## 故障排查

### 问题 1：Webhook 请求失败

**检查项**：

1. 服务器防火墙是否开放端口
2. Webhook URL 是否正确
3. Token 是否匹配
4. Nginx 配置是否正确（如果使用）

**调试方法**：

```bash
# 查看 Webhook 服务日志
pm2 logs webhook-server

# 手动测试 Webhook
curl -X POST http://localhost:3009/api/deploy/webhook \
  -H "Authorization: Bearer your-token" \
  -H "Content-Type: application/json" \
  -d '{"tag":"latest","status":"success"}'
```

### 问题 2：镜像拉取失败

**可能原因**：

1. 未登录阿里云容器镜像服务
2. 镜像标签不存在
3. 网络连接问题

**解决方法**：

```bash
# 手动登录
docker login --username=all丶亦然 crpi-eg9062f6byi3012b.cn-chengdu.personal.cr.aliyuncs.com

# 测试拉取
docker pull crpi-eg9062f6byi3012b.cn-chengdu.personal.cr.aliyuncs.com/dawn_dockers/qm-photo-server:latest
```

### 问题 3：服务启动失败

**检查项**：

1. 查看容器日志：`docker-compose -f docker-compose.prod.yml logs app`
2. 检查环境变量：确保 `.env.production` 配置正确
3. 检查数据库连接：确保 MySQL 和 Redis 正常运行
4. 检查端口占用：确保 3008 端口未被占用

**调试方法**：

```bash
# 查看服务状态
docker-compose -f docker-compose.prod.yml ps

# 查看应用日志
docker-compose -f docker-compose.prod.yml logs -f app

# 进入容器调试
docker exec -it qm-photo-app-prod sh
```

## 安全建议

### 1. Webhook Token 安全

- 使用强随机字符串作为 Token
- 定期更换 Token
- 不要在代码中硬编码 Token

### 2. 服务器安全

- 使用 HTTPS（配置 SSL 证书）
- 限制 Webhook 端点的访问 IP（如果可能）
- 使用防火墙限制端口访问

### 3. 部署权限

- 使用非 root 用户运行部署脚本
- 限制部署脚本的执行权限
- 记录所有部署操作日志

- **生产环境**：使用 **Webhook 自动部署**，实时响应，自动化程度高

- **紧急情况**：使用 **手动部署**，完全可控
