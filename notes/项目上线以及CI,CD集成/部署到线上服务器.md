## 部署方案的选择

在开始部署之前，我调研了几种常见的部署方式：

### 快速对比

| 方案                        | 我的评价                 | 是否考虑 |
| --------------------------- | ------------------------ | -------- |
| **手动部署 Docker**         | 太麻烦，每次都要手动操作 | ❌       |
| **面板部署（宝塔/1Panel）** | 可视化，适合我这种懒人   | ✅       |
| **Docker Compose**          | 配置简单，管理方便       | ✅       |
| **Kubernetes**              | 太复杂，我的项目用不上   | ❌       |
| **Serverless**              | 不适合有状态服务         | ❌       |

### 核心区别（简单说）

- **手动 vs 自动化**：手动太累，自动化省心
- **单容器 vs 多容器**：我的项目需要 MySQL、Redis 和 App，必须多容器
- **简单 vs 复杂**：Kubernetes 太复杂，Docker Compose 够用了

最终我选择了 **宝塔面板 + Docker Compose** 的组合，原因下面详细说。

## 为什么选择宝塔面板 + Docker Compose

### 我的考虑

作为一个独立开发者，我需要一个既简单又强大的部署方案。经过对比，我选择了 **宝塔面板 + Docker Compose**，原因如下：

#### 1. 项目规模匹配

我的项目是一个中小型的 NestJS 后端服务，包含：

- 一个应用服务（Node.js）
- MySQL 数据库
- Redis 缓存

这种规模用 Kubernetes 太浪费，手动管理又太累，Docker Compose 刚刚好。

#### 2. 可视化操作，降低门槛

虽然我会用命令行，但有时候还是喜欢可视化操作。宝塔面板提供了：

- 文件管理：直接上传和编辑文件
- 容器管理：可视化查看和管理容器
- 日志查看：方便查看容器日志
- 资源监控：实时查看服务器资源使用

这对于我这种偶尔需要快速操作的人来说，非常方便。

#### 3. 便于 CI/CD 自动化

这是最重要的原因。我的目标是实现完全自动化的 CI/CD：

- **容器化**：使用 Docker 镜像，GitHub Actions 构建完成后直接推送
- **配置管理**：Docker Compose 文件可以版本化管理，修改配置只需要改文件
- **快速更新**：通过更新镜像标签，`docker-compose up -d --no-deps app` 就能完成更新
- **回滚简单**：如果需要回滚，只需要指定之前的镜像标签即可

#### 4. 成本为零

- 宝塔面板：免费
- Docker Compose：免费
- 资源占用：相比 Kubernetes 少很多

对于个人项目来说，这是最经济的选择。

#### 5. 学习成本低

我不需要深入学习 Kubernetes 的复杂概念，Docker Compose 的配置足够直观，宝塔面板的操作也很简单，可以快速上手。

## 我的部署实践

### 第一步：服务器环境准备

我的服务器是阿里云 ECS，系统是 CentOS。首先安装宝塔面板：

```bash
yum install -y wget && wget -O install.sh http://download.bt.cn/install/install_6.0.sh && sh install.sh
```

安装完成后，通过浏览器访问宝塔面板，然后在「软件商店」中安装 Docker。

### 第二步：创建项目目录

在宝塔面板的「文件」中，我创建了项目目录：

```
/www/server/panel/data/compose/qm-photo-mysql-prod
```

这个路径是宝塔面板默认的 Docker Compose 项目路径。在这个目录下，我需要放置：

- `docker-compose.yaml`：容器编排配置
- `.env`：环境变量配置
- `logs/`：日志目录（会被挂载到容器中）

### 第三步：配置 Docker Compose

我创建了 `docker-compose.yaml` 文件，配置如下：

```yaml
services:
  # MySQL 数据库
  mysql:
    image: mysql:8.0
    container_name: qm-photo-mysql-prod
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: ${DB_DATABASE}
      MYSQL_USER: ${DB_USERNAME}
      MYSQL_PASSWORD: ${DB_PASSWORD}
    ports:
      - '${DB_PORT:-3306}:3306'
    volumes:
      - mysql-data-prod:/var/lib/mysql
    networks:
      - qm-photo-network-prod
    healthcheck:
      test: ['CMD', 'mysqladmin', 'ping', '-h', 'localhost']
      interval: 10s
      timeout: 5s
      retries: 5

  # Redis 缓存
  redis:
    image: redis:7-alpine
    container_name: qm-photo-redis-prod
    restart: unless-stopped
    command: redis-server --appendonly yes
    ports:
      - '${REDIS_PORT:-6379}:6379'
    volumes:
      - redis-data-prod:/data
    networks:
      - qm-photo-network-prod

  # 应用服务
  app:
    image: ${DOCKER_IMAGE:-crpi-eg9062f6byi3012b.cn-chengdu.personal.cr.aliyuncs.com/dawn_dockers/qm-photo-server:${DOCKER_IMAGE_TAG:-latest}}
    container_name: qm-photo-app-prod
    restart: unless-stopped
    ports:
      - '${PORT:-3008}:3008'
      - '${WEBHOOK_PORT:-3009}:3009'
    environment:
      - NODE_ENV=production
      - DB_HOST=mysql
      - REDIS_HOST=redis
      - WEBHOOK_TOKEN=${WEBHOOK_TOKEN}
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    volumes:
      - ./logs:/app/logs
    networks:
      - qm-photo-network-prod
    healthcheck:
      test: ['CMD', 'sh', '-c', 'pm2 list | grep -q "online"']
      interval: 30s
      timeout: 10s
      retries: 3

volumes:
  mysql-data-prod:
  redis-data-prod:

networks:
  qm-photo-network-prod:
    driver: bridge
    ipam:
      driver: default
      config:
        - subnet: 172.20.0.0/16
          gateway: 172.20.0.1
```

**配置说明**：

1. **MySQL 服务**：使用健康检查，确保数据库启动后再启动应用
2. **Redis 服务**：启用持久化，数据不会丢失
3. **应用服务**：使用环境变量 `DOCKER_IMAGE_TAG` 控制镜像版本
4. **网络配置**：显式指定子网，解决宝塔面板的网络问题
5. **健康检查**：应用使用 PM2 管理，通过检查 PM2 状态判断健康

### 第四步：配置环境变量

在项目目录下创建 `.env` 文件，配置数据库、Redis 等环境变量：

```env
# 数据库配置
DB_HOST=mysql
DB_PORT=3306
DB_USERNAME=root
DB_PASSWORD=your_password
DB_DATABASE=qm_photo

# Redis 配置
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=

# 应用配置
PORT=3008
NODE_ENV=production

# Docker 镜像配置（这个会在 CI/CD 中动态更新）
DOCKER_IMAGE_TAG=latest
```

**注意**：`.env` 文件包含敏感信息，不要提交到 Git 仓库。

### 第五步：首次启动服务

在宝塔面板的「终端」中，进入项目目录并启动服务：

```bash
cd /www/server/panel/data/compose/qm-photo-mysql-prod
docker-compose up -d
```

启动后，可以通过以下命令查看状态：

```bash
# 查看所有容器状态
docker-compose ps

# 查看应用日志
docker-compose logs -f app
```

也可以在宝塔面板的「Docker」→「容器」中可视化查看。

### 第六步：更新服务（手动方式）

当需要更新应用时，可以手动执行：

```bash
# 1. 拉取最新镜像
docker pull crpi-eg9062f6byi3012b.cn-chengdu.personal.cr.aliyuncs.com/dawn_dockers/qm-photo-server:latest

# 2. 更新环境变量（如果需要）
export DOCKER_IMAGE_TAG=latest

# 3. 重启应用服务（使用 --no-deps 只更新 app，不影响 MySQL 和 Redis）
docker-compose up -d --no-deps app
```

**关键点**：使用 `--no-deps` 参数很重要，这样只会更新应用服务，不会影响 MySQL 和 Redis，避免数据丢失。

### 第七步：自动化更新（CI/CD）

手动更新太麻烦，我配置了 GitHub Actions 自动部署。当代码推送到 master 分支时：

1. GitHub Actions 自动构建 Docker 镜像
2. 推送到阿里云容器镜像服务
3. 通过 SSH 连接到服务器
4. 执行部署脚本 `update.sh`
5. 脚本自动拉取镜像、运行迁移、重启服务

这样就实现了完全自动化的部署流程（详见后续文章）。

## 遇到的问题和解决方案

### 问题 1：宝塔面板创建容器时网络报错

**错误信息**：

```
容器编辑成功，当前指定的【qm-photo-mysql-prod_qm-photo-network-prod】网络创建时未指定子网，无法自定义IP
```

**解决方案**：
在 `docker-compose.yaml` 中为网络显式指定子网：

```yaml
networks:
  qm-photo-network-prod:
    driver: bridge
    ipam:
      driver: default
      config:
        - subnet: 172.20.0.0/16
          gateway: 172.20.0.1
```

### 问题 2：容器内服务无法访问 MySQL

**问题**：应用容器无法连接到 MySQL 容器

**解决方案**：

- 确保使用 Docker Compose 的网络，容器之间通过服务名访问
- 检查 `depends_on` 配置，确保启动顺序正确
- 验证环境变量 `DB_HOST=mysql`（不是 `localhost`）

### 问题 3：更新服务时数据丢失

**问题**：使用 `docker-compose up -d` 更新时，MySQL 数据丢失

**解决方案**：

- 使用 `--no-deps` 参数，只更新应用服务：`docker-compose up -d --no-deps app`
- 确保数据卷正确挂载：`volumes: - mysql-data-prod:/var/lib/mysql`
- 定期备份数据卷

### 问题 4：日志文件权限问题

**问题**：容器内应用无法写入日志文件

**解决方案**：

- 在 `docker-compose.yaml` 中设置正确的用户权限
- 或者在启动脚本中设置：`chown -R www:www ./logs`

## 与 CI/CD 的集成

### 为什么需要 CI/CD

手动部署虽然可行，但每次都要：

1. 登录服务器
2. 拉取镜像
3. 运行迁移
4. 重启服务

太麻烦了！而且容易出错。

### 我的 CI/CD 流程

我配置了 GitHub Actions，实现了完全自动化：

1. **代码推送** → 触发 GitHub Actions
2. **自动构建** → 构建 Docker 镜像并推送到阿里云
3. **自动部署** → SSH 连接服务器，执行 `update.sh` 脚本
4. **自动通知** → 发送邮件通知构建和部署结果

整个过程完全自动化，我只需要推送代码，剩下的都交给 CI/CD。

### 部署脚本的作用

`update.sh` 脚本做了这些事情：

1. **登录镜像仓库**：使用传入的密码登录
2. **拉取最新镜像**：根据标签拉取对应版本的镜像
3. **运行数据库迁移**：确保数据库结构是最新的
4. **更新服务**：使用 `--no-deps` 只更新应用，不影响数据库
5. **健康检查**：验证服务是否正常启动

这样每次更新都是安全、可靠的。

## 总结

### 我的选择总结

经过实践，**宝塔面板 + Docker Compose** 这个组合对我来说是完美的：

- ✅ **简单**：配置直观，操作方便
- ✅ **强大**：支持多容器编排，满足项目需求
- ✅ **自动化**：与 CI/CD 完美集成
- ✅ **免费**：不需要额外成本
- ✅ **可视化**：宝塔面板提供友好的管理界面

### 给其他开发者的建议

如果你也是独立开发者或者小团队，我建议：

1. **不要过度设计**：Kubernetes 很强大，但你的项目可能不需要
2. **选择熟悉的工具**：宝塔面板虽然"不够酷"，但确实好用
3. **自动化是必须的**：手动部署太累，CI/CD 一定要配置
4. **版本化管理**：Docker Compose 文件和脚本都要提交到 Git
5. **定期备份**：数据卷要定期备份，避免数据丢失
