# 环境变量配置集成笔记

## 📝 集成步骤记录

### 1. 安装依赖

```bash
pnpm add @nestjs/config
```

### 2. 创建配置文件结构

#### 配置文件组织原则

- **`.env`** - 公共配置（所有环境共享）
  - 包含：PORT、DB_HOST、DB_PORT、DB_USERNAME、JWT_EXPIRES_IN 等
  - 原则：如果配置在所有环境都相同，放在这里

- **`.env.development`** - 开发环境特有配置
  - 包含：NODE_ENV、DB_DATABASE、DB_PASSWORD、DATABASE_URL、JWT_SECRET、CORS_ORIGIN、LOG_LEVEL 等
  - 原则：只放开发环境独有的配置

- **`.env.production`** - 生产环境特有配置
  - 包含：NODE_ENV、DB_DATABASE、DB_PASSWORD、DATABASE_URL、JWT_SECRET、CORS_ORIGIN、LOG_LEVEL 等
  - 原则：只放生产环境独有的配置

### 3. 创建配置模块文件

#### `src/config/app.config.ts`
```typescript
import { registerAs } from '@nestjs/config';

export default registerAs('app', () => ({
  port: parseInt(process.env.PORT || '3000', 10),
  nodeEnv: process.env.NODE_ENV || 'development',
  jwtSecret: process.env.JWT_SECRET || 'default-secret-key',
  jwtExpiresIn: process.env.JWT_EXPIRES_IN || '7d',
  corsOrigin: process.env.CORS_ORIGIN || 'http://localhost:3000',
  logLevel: process.env.LOG_LEVEL || 'debug',
}));
```

#### `src/config/database.config.ts`
```typescript
import { registerAs } from '@nestjs/config';

export default registerAs('database', () => ({
  host: process.env.DB_HOST || 'localhost',
  port: parseInt(process.env.DB_PORT || '3306', 10),
  username: process.env.DB_USERNAME || 'root',
  password: process.env.DB_PASSWORD || '123456',
  database: process.env.DB_DATABASE || 'qm_photo_db',
  url: process.env.DATABASE_URL,
}));
```

### 4. 在 SharedModule 中集成（推荐架构）

**创建 `src/shared/shared.module.ts`：**

```typescript
import { Global, Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import appConfig from '../config/app.config';
import databaseConfig from '../config/database.config';

/**
 * 共享模块 - 包含全局配置和公共服务
 * 
 * 使用 @Global() 装饰器使模块全局可用，无需在其他模块中导入
 */
@Global()
@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      load: [appConfig, databaseConfig],
      envFilePath: [
        '.env',                                    // 1. 先加载公共配置
        `.env.${process.env.NODE_ENV || 'development'}`, // 2. 再加载环境特定配置（会覆盖）
      ],
      expandVariables: true,
    }),
  ],
  exports: [ConfigModule],
})
export class SharedModule {}
```

**在 `src/app.module.ts` 中导入：**

```typescript
import { Module } from '@nestjs/common';
import { SharedModule } from './shared/shared.module';

@Module({
  imports: [SharedModule],
  // ... 其他配置
})
export class AppModule {}
```

**关键点：**
- `@Global()` - 使 SharedModule 全局可用，其他模块无需导入即可使用 ConfigService
- `isGlobal: true` - 使 ConfigModule 全局可用
- `envFilePath` - 配置加载顺序，后加载的会覆盖先加载的
- `expandVariables: true` - 支持在配置中使用 `${VAR}` 语法
- **架构优势**：将全局配置集中管理，便于维护和扩展

### 5. 在 main.ts 中使用配置

```typescript
import { NestFactory } from '@nestjs/core';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  
  const configService = app.get(ConfigService);
  const port = configService.get<number>('app.port', 3000);
  const nodeEnv = configService.get<string>('app.nodeEnv', 'development');
  
  // 启用 CORS
  const corsOrigin = configService.get<string>('app.corsOrigin');
  app.enableCors({
    origin: corsOrigin,
    credentials: true,
  });
  
  await app.listen(port);
  
  console.log(`🚀 应用运行在: http://localhost:${port}`);
  console.log(`📦 环境: ${nodeEnv}`);
}
bootstrap();
```

### 6. 配置 package.json 脚本

```json
{
  "scripts": {
    "start:dev": "NODE_ENV=development nest start --watch",
    "start:prod": "NODE_ENV=production node dist/main",
    "build:prod": "NODE_ENV=production nest build"
  }
}
```

## 🔄 如何给其他项目搭建环境

### 快速复制步骤

1. **复制配置文件结构**
   ```bash
   # 复制配置模块文件
   cp -r src/config/ <新项目>/src/
   
   # 复制环境配置文件
   cp .env <新项目>/
   cp .env.development <新项目>/
   cp .env.production <新项目>/
   ```

2. **安装依赖**
   ```bash
   cd <新项目>
   pnpm add @nestjs/config
   ```

3. **创建 SharedModule 并集成配置**
   - 创建 `src/shared/shared.module.ts`
   - 使用 `@Global()` 装饰器
   - 配置 `ConfigModule.forRoot()`
   - 导入 `appConfig` 和 `databaseConfig`

4. **在 AppModule 中导入 SharedModule**
   - 在 `AppModule` 的 `imports` 中添加 `SharedModule`

4. **更新配置值**
   - 根据新项目的实际需求修改 `.env`、`.env.development`、`.env.production` 中的配置值
   - 特别注意：数据库连接、JWT密钥、CORS域名等

5. **更新 package.json 脚本**
   - 复制 `start:dev`、`start:prod`、`build:prod` 脚本

### 配置检查清单

- [ ] `.env` 包含所有公共配置
- [ ] `.env.development` 只包含开发环境特有配置
- [ ] `.env.production` 只包含生产环境特有配置
- [ ] `src/config/` 目录下有对应的配置文件
- [ ] `src/shared/shared.module.ts` 中正确配置了 `ConfigModule`
- [ ] `AppModule` 中导入了 `SharedModule`
- [ ] `main.ts` 中使用 `ConfigService` 读取配置
- [ ] `package.json` 中有正确的启动脚本
- [ ] `.gitignore` 正确配置，允许提交环境配置文件

## 💡 关键要点

1. **配置分离原则**
   - 公共配置 → `.env`
   - 环境特定配置 → `.env.{environment}`
   - 避免重复，保持简洁

2. **加载顺序**
   - 先加载公共配置（`.env`）
   - 再加载环境特定配置（`.env.{NODE_ENV}`）
   - 后加载的会覆盖先加载的同名配置

3. **使用方式**
   - 在服务中注入 `ConfigService`
   - 使用 `configService.get('namespace.key')` 获取配置
   - 提供默认值作为第二个参数

4. **环境切换**
   - 通过 `NODE_ENV` 环境变量控制
   - 开发环境：`NODE_ENV=development`
   - 生产环境：`NODE_ENV=production`
